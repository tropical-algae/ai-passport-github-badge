# GitHub Pixel Passport 应用说明

GitHub Pixel Passport 是为 FoloToy AI Passport 打造的七页、240 × 320 GitHub 铭牌，目标硬件为 ESP32-C3、8 MB Flash、无 PSRAM，使用 ESP-IDF 5.5.3。应用通过公开 GitHub REST 数据、本地 Wi-Fi 配置页与持久化缓存工作。安装和日常使用请先阅读[项目 README](../../README.zh_CN.md)。

## 应用结构

| 模块 | 职责 |
| --- | --- |
| `main/badge_app.c` | 启动、后台任务归属、配置交接、调度与界面发布 |
| `main/badge_input.c`、`badge_idle.c`、`badge_ui_state.c` | 按键手势、熄屏唤醒与纯导航状态 |
| `main/badge_ui.c` | LVGL 绘制、页面布局、缓存头像解码、二维码弹窗与反馈 |
| `main/badge_network.c`、`badge_portal.c`、`badge_portal.html` | Wi-Fi、本地 HTTP/DNS 配置、网络扫描与表单验证 |
| `main/badge_sync.c`、`badge_sync_parse.c`、`badge_sync_logic.c` | 有界 HTTP 采集、JSON 解析、额度/游标处理与事件去重 |
| `main/badge_model.c`、`badge_storage.c`、`badge_backup.c` | 数据校验、快照、NVS 偏好与事务式备份恢复 |
| `components/bsp` | 屏幕、按键、电池及其他板级支持 |

原始测试菜单和 Demo 源码保留作参考，不参与铭牌构建。应用逻辑不放入 BSP。按键回调只将边沿事件入队，不执行网络或存储操作；访问 UI 和修改界面持有的数据模型共用 BSP 的 LVGL 锁。HTTP、解析与持久化写入在绘制回调外执行。

## 页面与操作

| 页面 | 内容与交互 |
| --- | --- |
| PROFILE | 用户名、昵称、头像、公司、位置、网站、加入日期、公开仓库/关注者/关注数。短按 OK 切换主页二维码；有意不显示个人简介与总 Stars。 |
| REPOSITORIES | 按 Stars 排名前三的仓库，包含 Fork。UP/DOWN 选择仓库并查看对应 Stars、Forks 与 Watchers。 |
| LANGUAGES | 原创仓库、全部仓库或前五个仓库之一。显示前五种语言与 OTHER；圆环中心的长名称使用省略号。 |
| ACTIVITY | 以周日为一周起点的 24 周已观测事件网格，以及近期 PushEvent 频次。未知、部分覆盖、确认零值与未来日期分别表示。 |
| PR/ISSUES | 用户创建的公开 PR/Issue 统计。UP/DOWN 移动标签焦点，OK 激活。 |
| STARS/GISTS | 已采样的收藏仓库与公开 Gists。UP/DOWN 移动标签焦点，OK 激活。 |
| TIMELINE | 六条近期公开事件。 |

长按 UP/DOWN 600 毫秒切页，长按 OK 进入/退出设置，短按 UP/DOWN 调整当前选择。二维码弹窗会接收但不响应 UP/DOWN，短按 OK 关闭。PROFILE 的头像区域保持原有外观，同时承担打开主页二维码的动作。

主设置列表依次为 BRIGHTNESS、AUTO SCREEN OFF、COLOR THEME、CONNECT WI-FI、REFETCH DATA。亮度可选 100/80/60/40/20/10%；熄屏时间可选 1/5/10/30/60 分钟或 NEVER，默认 10 分钟。五种主题为 Phosphor Green、Industrial Yellow、Ice Cyan、Amethyst、Copper Rose。确认外观选项后回到对应主设置行，即使确认的是当前值也一样。这些子菜单没有 BACK 行，通过长按 OK 退出设置。

空闲时间从最后一次按键活动计算。超时会将背光 PWM 停在低电平，发送 LCD 关闭显示与 Sleep In 命令，并暂停显示刷新，但不停止联网和同步。任意按键先唤醒 LCD、重绘完整画面并等待显示传输结束，再恢复已保存亮度；整次唤醒手势被消费。显示切换失败时保持输入阻断并限频重试，避免假报成功或操作看不见的页面。可恢复的熄屏路径保留 SPI、GPIO 所有权与应用运行，不调用终端深睡接口。账号配置完成后会持久保存偏好。电池和本地时钟值未知时显示占位。内置 10 像素回退字体覆盖文档记录的中日韩文字与标点；范围外字符（包括 emoji）使用可见缺字方框。

## 显示省电与空闲任务

默认配置启用 ESP-IDF 动态调频：CPU 空闲时可降至 40 MHz 晶振频率，处理任务时使用 160 MHz。
背光改用晶振时钟，避免 APB 频率变化影响 PWM。依据官方[电源管理说明](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/system/power_management.html)
及 [LEDC 时钟与停止接口](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/peripherals/ledc.html)。
隔离验证与发布构建使用这些默认值；已有本地 sdkconfig 也需要启用 `CONFIG_PM_ENABLE` 和 `CONFIG_PM_DFS_INIT_AUTO`。

第一次熄屏后，以连续的单调时钟回调替换 LVGL 的 5 ms 周期 tick。只暂停显示刷新，其他 LVGL 定时器仍按真实时间运行。
避免全局禁用 timer handler，因为 LVGL 9.5 在该状态下向 port 返回 1 ms 等待，反而会造成频繁轮询。
后台布局请求不能恢复休眠屏幕的刷新；SPI 提交被拒绝时会释放 LVGL 的刷新等待，让唤醒流程能报告错误并重试。

应用熄屏后的空闲检查间隔最多 250 ms，按键入队立即打断等待。普通网络空闲等待最多一秒，临近连接期限时提前醒来。
配网、扫描和备份仍保留 100 ms 检查，网络事件入队立即唤醒任务。等待按键时不占用备份维护锁。

熄屏后继续保持 Wi-Fi、按键检测与定时同步，不进入 CPU 浅睡或深睡。Wi-Fi 使用 IDF 默认的最小 modem-sleep 模式，
开启的配网热点仍会消耗电量。铭牌不会启动 I2S/音频驱动。这些代码事实不能证明整板电流或实际续航；
更新前后应在相同 Wi-Fi、热点和亮度条件下比较，有条件时测量电流。LCD 残留轮廓与熄屏唤醒表现仍需真机验收。

## Wi-Fi 配置与账号切换

未配置的铭牌会开启临时 WPA2 热点，生成凭证，并同时显示 Wi-Fi 二维码及供手动输入的完整热点名和密码。每次新会话生成新密码；手机沿用旧凭据时，可能需要先忽略已保存网络再加入。热点一次允许一台手机连接。二维码按整数像素绘制码点，四周保留至少四个码点宽的白边。手机连入后，如果配置页没有自动打开，可访问 `http://192.168.4.1`。页面扫描附近 2.4 GHz 网络，按 SSID 去重，按信号强度显示最多 16 项；支持重新扫描与手动输入隐藏网络。

保存项包括 Wi-Fi 名称/密码、公开 GitHub 用户名，以及 1–168 小时的整数同步间隔，默认 6 小时。浏览器提供 UTC 偏移供时钟显示；它是固定偏移，不是自动切换夏令时的时区数据库。不接受 GitHub 密码或 Token。页面不会返回已保存的 Wi-Fi 密码；密码留空仅在 SSID 相同时保留原密码，无密码网络通过明确的开放网络选项处理。暂不支持企业认证或需要网页登录的 Wi-Fi。

先测试连接，再替换保存的凭证。只有目标 Wi-Fi 获得 IP 且配置持久化成功，提交才算完成。浏览器确认收到保存结果后自动关闭热点；手机已离开时由短暂且有上限的等待兜底。配网弹窗在自己的热点会话真正结束后关闭，不再单独保留 60 秒热点。连接或保存失败会保留原来的已保存配置，并通过主题色提示框反馈。仅更改账号或同步间隔时，如果原 Wi-Fi 连接仍有效且凭据未变，无需重新连接。

每次开关意图都与实际热点及服务状态核对。会话标识防止旧结果关闭新弹窗或显示旧凭据。关闭配网只结束 AP/HTTP/DNS，保留连接路由器的模式及已经受理的连接与保存任务，不取消 GitHub 采集；手动关闭后完成的提交仍在设备上提示。服务切换失败时保留忙碌状态并重试，仅在当前会话完全就绪后显示凭据。GitHub HTTPS 等待配置服务关闭且已受理的配网事务完成，分开内存峰值，也避免在配置尚未提交时为旧账号启动采集。

配网弹窗暂停自动熄屏，关闭后重新开始计时。备份维护期间只允许关闭配网的手势；关闭热点会中断手机传输，但已经进入提交阶段的存储操作继续完成，已成功恢复的重启也继续执行。维护期间其余偏好修改和同步仍受阻止。

同步期间打开 CONNECT WI-FI，会等待当前后台任务完成；弹窗显示 FETCH IN PROGRESS / SETUP AFTER FETCH。关闭弹窗只取消尚未开启的热点请求，或关闭当前热点，不取消已经受理的提交。更改用户名会使旧账号的在途采集失效，并加载新账号自己的缓存；没有缓存时显示空状态，等待首次同步。

配置页页脚为 `powered by TROPICALALGAE's codex`，其中只有名字链接到 [TROPICALALGAE](https://github.com/tropical-algae)，以带 `noopener noreferrer` 的新标签页打开。

## 后台采集与反馈

触发后的同步归后台任务管理。退出设置、切换页面、修改外观或熄屏都不会取消同步。HTTPS 前需要有效网络时间。缓存尚新时，设备重启不会强制刷新；离线期间到期的刷新会在重连后执行，并遵守额度等待时间。

采集器请求七个页面需要的数据，并保存检查点。一个接口失败时，其他独立部分仍可继续；新的数据准备好之前保留已有完整缓存。PROFILE 后即下载头像，渲染不请求图片 URL。只有快照持久化成功后才推进检查点。重试未完成的采集时，继续失败或未完成的部分，不丢弃已完成的部分。

REFETCH DATA 会显示启动和结束反馈，区分全部成功、公开数据部分完成、网络/TLS/HTTP 错误、等待时钟、等待额度和存储失败。双行反馈尽可能给出接口与原因，额度倒计时随时间更新。普通网络失败可手动立即重试；服务端施加的核心 API、搜索和头像服务等待时间会持久保留，重启或开启新一轮采集不能绕过。

请求直接访问 GitHub 与头像 CDN。受限网络，包括中国大陆的部分网络，可能无法稳定连接。铭牌保留离线缓存并说明失败部分，不提供代理。未知历史或不可用的部分不会悄悄变成编造的零值。

## 公开数据的边界

| 数据 | 含义与限制 |
| --- | --- |
| 仓库 | 分页读取，不设应用层仓库总数上限。保留前五个供页面选择和语言范围使用，仓库页显示前三个。 |
| Watchers | 使用 `subscribers_count`；`watchers_count` 实际是 Stars 别名。 |
| 语言 | 原创/全部仓库和前五个独立仓库的字节数聚合。最多保留 128 个命名聚合项，更多语言并入 OTHER 并标记部分数据；图表显示前五项加 OTHER。 |
| 活动 | 按 UTC 日期分组的公开事件与 PushEvent 频次，不等于提交数或 GitHub 贡献日历；24 周历史在本地去重积累。 |
| PR/Issue 统计 | 在公开仓库中搜索由用户创建的条目；`incomplete_results` 标记部分统计。分布图的 Closed PR 排除 Merged，合并率分母为全部 PR。 |
| Stars/Gists | 各接口前 100 条，达到上限时使用样本/数量标签与部分标记；保留两条供详情展示。 |
| 时间线 | 六条近期公开事件，与活动页共用采集结果。 |
| 头像 | 仅允许 HTTPS `avatars.githubusercontent.com`，不跟随重定向；最多 24 KiB、64 × 64 像素。支持基线 JPEG 和每通道不超过 8 位的 PNG，包括 RGB/RGBA、调色板、灰度、透明度及 Adam7 交错。16 位 PNG、渐进 JPEG、GIF 和 WebP 会安全拒绝。若没有可用头像，不支持或损坏的图片使用占位图。 |

GitHub 事件时间线最多提供最近 30 天内的 300 条事件。更早的历史以及离线或条数上限导致的缺口保留为未知或部分覆盖；24 周布局不代表服务端提供 24 周历史。参见 [GitHub 事件限制](https://docs.github.com/en/rest/activity/events#about-github-events)。

匿名 REST 请求按出口公网 IP 共享每小时 60 次的主额度，搜索接口有单独且更严格的限制。大型仓库/语言采集可能跨越多个额度窗口。参见 [REST 额度限制](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)和 [Watching 与 Starring 的区别](https://docs.github.com/en/rest/activity/starring#starring-versus-watching)。

HTTP 响应体和单个 JSON 对象都有大小上限。截断、格式错误的响应会校验失败；过大事件会跳过并标记部分覆盖。一份成功保存的部分数据快照表示它可用且覆盖有限，不表示已获取全部公开记录。

## 头像与内存归属

编码后的头像保存在 Flash 中，供离线使用。应用在网络任务释放内存之后、待开启热点启动之前读取并解码。UI 将结果复制到自己持有的 54 × 54 RGB565 缓冲区，必要时附加独立 Alpha 平面；调用结束后应用释放编码字节。完整图像采样覆盖全部源像素范围，也处理流式 JPEG 解码区域。JPEG 字节通过 LVGL 公开的内存文件系统路径解码，借用的输入释放之前会关闭临时解码器和缓存引用。

解码失败时保留已有有效头像，之后可重试；切换账号会清除旧头像。绘制只使用自有像素，不下载或反复解码。无透明度时像素缓冲占 5,832 字节，Alpha 平面额外占 2,916 字节。解码临时状态分配在堆上，以保护较小的应用栈。

LVGL 共用普通 IDF 堆，不预留闲置固定内存池。BSP 使用一个 240 × 40 RGB565 DMA 显示缓冲。网络、配置页和头像解码的内存峰值分开，不依赖 PSRAM。本机分配测试通过不能证明实际设备的堆/栈余量。

公共头像门禁会在下载结果写入缓存、接受备份或调用 UI 解码器之前，验证完整的 PNG IHDR、允许的颜色/位深组合、压缩/过滤方法和交错方式。固定版本 LVGL 9.5.0 的 LodePNG 适配中，`decodeGeneric()` 分配每像素四字节缓冲后，`postProcessScanlines()` 会先写入源格式像素，而 RGB16/RGBA16 实际需要每像素六/八字节。公共门禁拒绝所有 16 位 PNG，以避开该不安全路径，无需修改第三方依赖。像素对比夹具覆盖允许的 PNG 格式，内存检查回归验证 16 位 RGB/RGBA 不会进入解码器。

## 持久化、备份与刷写

| 分区 | 偏移 | 大小 | 用途 |
| --- | --- | --- | --- |
| `nvs` | `0x9000` | `0x6000` | Wi-Fi、偏好与当前缓存命名空间 |
| `phy_init` | `0xf000` | `0x1000` | 无线校准数据 |
| `factory` | `0x10000` | `0x6f0000` | 铭牌应用 |
| `badge_data` | `0x700000` | `0x100000` | SPIFFS 快照、头像、事件日志与同步游标 |

快照使用双槽并检查 schema、账号、代数和 CRC。暂存文件替换保留可恢复的备份，中断写入在启动时恢复。优先使用最新有效槽，不把 I/O 错误当作较新记录不存在的证据。SPIFFS 文件存在性检查使用其 VFS 支持的操作。已有内容却无法挂载的分区会保留，只有完全擦空的铭牌数据分区才自动格式化。空间用尽时报告失败并保留旧有效记录，不自动清理旧账号缓存。

EXPORT BACKUP 和 RESTORE BACKUP 独立于普通配置表单。导出包含**已保存**配置、当前账号最新模型、头像、累计活动和事件去重 ID；不包含未保存表单修改、其他账号和未完成同步游标。备份中的 Wi-Fi 密码为明文，需要私密保存。

导入上限为 128 KiB，检查 schema、CRC、字符串、数组、数值边界和日志完整性。文件先暂存至未使用的命名空间，再由一个 NVS 记录同时激活配置与命名空间。无效上传或写入失败保持当前配置；NVS 提交结果不确定时保留两套文件。成功后页面确认导入，铭牌三秒后重启，使用导入的 Wi-Fi、用户名和间隔。如果该 Wi-Fi 不可用，导入数据仍可离线浏览，可重新打开配网更换网络。备份/恢复期间暂时冻结设置修改与同步，保证数据一致。

不含熄屏字段的旧配置使用默认 10 分钟，并保留原缓存命名空间。新备份包含选择的熄屏时间，不支持该扩展格式的旧固件无法导入。

兼容安装使用 app 镜像写入 `0x10000`，不替换 NVS 与缓存分区。首次安装使用 full 镜像写入 `0x0`，它会替换引导程序和分区表，合并填充可能重置设置。升级前先导出，核对版本分区/清单，通常无需整片擦除。详见[发布指南](ci/CI-build-and-release.zh_CN.md)。

## 验证

激活 ESP-IDF 5.5.3 后运行：

```bash
./tools/validate.sh --static
./tools/validate.sh
./tools/render_badge_ui.sh build/github-ui-preview
BADGE_UI_CLIB_ALLOCATOR=ON ./tools/render_badge_ui.sh build/github-ui-preview-clib
```

检查覆盖仓库规则、纯按键/导航/计时模型、应用后台任务交互、配置页 JavaScript、存储/备份故障注入、真实 cJSON 采集器夹具、独立固件构建与合并镜像验证。本机 C/LVGL 测试检查页面渲染、字体覆盖、二维码、PNG/JPEG 内存归属、失败回退与低内存恢复。夹具均使用合成数据，输出是软件预览，不是真机照片，也不能证明手机扫码成功。

真机验收应覆盖冷启动、全部按键手势、扫描与配网成功/失败、二维码自动关闭、退出设置后后台同步、完整/部分/错误反馈、离线重启后的头像、熄屏唤醒、偏好持久化、备份恢复和累计历史去重。观察 AP、TLS 与图像操作期间的堆/栈余量。分别报告 Build、Host tests 和 Device tests，不能用构建代替真机测试。
